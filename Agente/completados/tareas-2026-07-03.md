## 037A-1 — Fix schema colecciones (500 en samples.nakomi.studio)

- **Que:** Los endpoints `GET /api/colecciones/explorar`, `GET /api/feed?tipo=descubrir` y `GET /api/feed?tipo=recientes` devolvían 500 Internal Server Error. Causa raíz: dos migraciones creaban `colecciones` con `CREATE TABLE IF NOT EXISTS`. La primera (`20260417000003_samples_core`) creaba la tabla sin `eliminado_en`; la segunda (`20260418000030_colecciones`) que incluía `eliminado_en` era no-op.
- **Fix producción:** `ALTER TABLE colecciones ADD COLUMN eliminado_en TIMESTAMPTZ` + rename `posicion→orden` en `coleccion_samples` + índices parciales `WHERE eliminado_en IS NULL`.
- **Fix template:** Eliminada la definición duplicada de `colecciones`/`coleccion_samples` de `20260417000003_samples_core.up.sql`. Creada migración correctiva `20260703000000_fix_colecciones_schema.up.sql` (idempotente, con down).
- **Archivos:** `migrations/20260417000003_samples_core.up.sql`, `migrations/20260703000000_fix_colecciones_schema.{up,down}.sql`
- **Gotchas:** coolify-manager exec CLI parser rompe comandos SQL con comas/espacios largos. Workaround: comandos individuales simples.
- **Sentinel:** No aplica (migración SQL, no código Rust/React)
- **GLORY:** No aplica (específico de kamples)
- **Latente detectado:** `coleccion_samples` tenía `posicion` (schema viejo) pero el código Rust usa `orden` (schema nuevo). Resuelto con rename.
