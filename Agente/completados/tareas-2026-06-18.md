## 186A-1 — Fix modal rendimiento algoritmo (HTTP 200 error)

- **Que:** El modal "Rendimiento del algoritmo" mostraba "HTTP 200" como error porque el frontend esperaba `{ok, historial}` pero el backend Rust devuelve `Vec<TimingEntry>` plano (array). Además las etapas (`etapas`) llegaban como `Vec<TimingStage>` (array de `{name, ms}`) pero el frontend esperaba un flat map `{ [nombre]: ms }`. Y las etiquetas hacían referencia a stages del PHP legacy que ya no existen en Rust.
- **Archivos:**
  - `frontend/src/legacy/stores/algoTimingStore.ts` — Rewrite completo del store: ahora parsea array response directamente, convierte `TimingStage[]` → flat `EtapasTiming`, mapea `meta` de snake_case, type safe.
  - `frontend/src/legacy/components/ui/ModalAlgoTiming.tsx` — Actualizadas `ETIQUETAS` a los nombres reales del RecommenderService Rust (`cache_fresh_hit`, `cache_fresh_miss`, `cache_stale_hit`, `cache_stale_miss`, `compute_and_cache`).
  - `src/handlers/admin.rs` — Añadido handler `algo_timing_clear` (DELETE) para "Limpiar" + registro en router.
  - `src/services/algo_timing.rs` — Añadido método `clear()` para vaciar historial.
- **Gotchas:** El `apiPeticion` retorna `data: (json.data ?? json)` — como el backend retorna array plano, `json.data` es `undefined`, cae a `json` (el array). La condición `res.data?.ok` fallaba porque un array no tiene `.ok`. Ahora se detecta con `Array.isArray(res.data)`.
- **Sentinel:** No aplica (falso positivo de tipo, no sintáctico).
- **GLORY:** No aplica (específico de este proyecto).
