## 175A-2 — WebP lossy + preload widths fix + initial data injection

- **Que:** Tres correcciones de LCP en paralelo:
  1. **WebP real**: reemplazado el fallback `JpegEncoder` en `OutputFormat::Webp` por `webp::Encoder::from_rgba` (crate `webp = "0.2"`, libwebp vendorizado). Content-Type ahora correcto `image/webp`. Lighthouse esperaba 2361 KiB de ahorro.
  2. **Preload widths**: `[400, 800, 1200]` → `[150, 300, 480, 640, 800, 1024, 1200, 1600, 2400]` (idéntico a `ALLOWED_WIDTHS` en `imageUtils.ts`). El browser ahora puede hacer cache-hit al crear el srcset del hero.
  3. **Initial data injection**: `prerender.rs` ahora hace UNA sola llamada `ProjectRepository::list_published` para la home page, extrae la imagen hero y serializa todos los proyectos como `window.__INITIAL_DATA__` en `</head>`. `App.tsx` pre-puebla React Query con esos datos antes de renderizar.
- **Archivos:**
  - `Cargo.toml` — añadido `webp = { version = "0.2", default-features = false }`
  - `src/services/image_processing.rs` — `OutputFormat::Webp` usa `webp::Encoder::from_rgba`
  - `src/middleware/prerender.rs` — eliminado `resolve_hero_image_url` (unused), añadidos `build_hero_preload_from_path` + `build_initial_data_script`, handler home restructurado
  - `frontend/src/App.tsx` — pre-puebla cache `['public-projects-showcase']` desde `window.__INITIAL_DATA__`
- **Gotchas:**
  - `Project` no deriva `Clone` → se extrae `hero_path: Option<String>` (clonar solo el String) antes de consumir el Vec con `into_iter()`
  - `webp::Encoder::from_rgba` no requiere el feature `image` del crate → `default-features = false`
  - `build_initial_data_script` toma `Vec<Project>` (ownership, no `&[Project]`) para evitar el Clone
  - libwebp se vendoriza vía `cc` — primera compilación tarda más en Docker (Rust builder ya tiene gcc)
- **Sentinel:** no aplica — no hay nueva regla automática
- **GLORY:** no aplica
