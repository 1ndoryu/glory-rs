### 166A-6 — Fix `DELETE /api/like` body parsing + add missing upload sample fields
- **Que:** Dos bugs de producción:
  1. `DELETE /api/like` devolvía 400 porque el handler usaba `Query<UnlikeQuery>` (query string) pero el frontend envía JSON body. Cambiado a `Json<UnlikeRequest>` (como `create_like`).
  2. Upload de sample no parseaba campos relacionales que envía el frontend (`cancion_origen_id`, `relacion_id`, `lado_relacion`, `inicio_segundos`, `tipo_elemento`, `portada`). Extendido `ParsedUpload`, `parse_upload_multipart`, `CreateUploadSampleParams`, SQL INSERT, y añadida lógica post-creación para actualizar `relaciones_sample` con `sample_fuente_id`/`sample_destino_id`, `tipo_elemento` y `timings_fuente`/`timings_destino` (JSONB).
- **Archivos:**
  - `src/handlers/likes.rs` — `Json<UnlikeRequest>` en vez de `Query<UnlikeQuery>`
  - `src/handlers/samples.rs` — campos relacionales + portada en upload
  - `src/repositories/sample.rs` — `CreateUploadSampleParams` extendido + `update_relacion_sample_link`
  - `src/models/sample.rs` — `UploadSampleRequestDoc` extendido
  - `src/services/extraccion_publisher.rs` — campos añadidos al constructor
- **Validación:** `cargo fmt --check` ✅, `cargo check` ✅, `cargo clippy --all-targets -- -D warnings` ✅, `cargo test` (184/184) ✅, `npm run type-check` ✅
- **Gotchas:**
  - `timings_fuente`/`timings_destino` son JSONB, no `integer[]`. Usar `to_jsonb($4::integer)`.
  - `sqlx::query!` no puede inferir `Option<i32>` en `CASE WHEN` + `to_jsonb`. Usar `sqlx::query` (runtime).
  - `update_relacion_sample_link` usa `sqlx::query` (untyped) para evitar regenerar cache offline.
- **Sentinel:** No aplica. Son bugs de contrato API (DELETE con body vs query) y campos faltantes en parseo multipart — detectables con tests de integración contra el handler real.
