## 256A-1c — Fix login Tauri + portada modal auth

- **Que:** Arreglado error de login en Tauri ("Respuesta del servidor no es JSON válido") causado porque `VITE_KAMPLES_BACKEND` no se pasaba como env var en tauri dev, dejando sin instalar el `wpJsonRustAdapter`. También arreglada la imagen de portada del modal login que no cargaba en Tauri.
- **Archivos:**
  - `clients/desktop/src/services/apiDesktopAdapter.ts` — Default a `'rust'` cuando `VITE_KAMPLES_BACKEND` no está definido
  - `clients/desktop/vite.config.ts` — Añadido `publicDir` con `frontend/public` para servir `/legacy-assets/*` en dev; añadido `frontend/public` a `fs.allow`
  - `frontend/src/legacy/utils/resolverRutaAsset.ts` — En Tauri DEV mode usa Vite dev server local para assets legacy; en producción sigue usando `https://kamples.com`
  - `frontend/src/legacy/components/auth/ModalAuth.tsx` — Quitado `loading="lazy"` de la imagen (browser intervention la difería en Tauri WebView)
- **Gotchas:** `publicDir` en Vite 6+ acepta arrays. El env var `VITE_KAMPLES_BACKEND` no se hereda automáticamente en tauri dev porque Tauri lanza Vite con su propio entorno. La solución fue default a `'rust'` en vez de confiar en que el env var siempre esté presente.
- **Sentinel:** no aplica
- **GLORY:** No aplica (específico del proyecto Kamples desktop)

## 256A-3 — Fix género modal + avatar en desktop app

- **Que:** Corregido bug donde el modal "¿Cuáles son tus géneros favoritos?" aparecía constantemente y la foto de perfil no cargaba en la app desktop (Tauri). La causa raíz era doble:
  1. **Response (GET):** `wpJsonRustAdapter.ts` no adaptaba la respuesta de `GET /users/me` de snake_case (Rust) a camelCase (frontend), dejando `generosPreferidos` y `avatarUrl` como `undefined` tras el refetch QK3.
  2. **Request (PATCH):** Cuando el usuario guardaba géneros vía el modal, el body `{ generosPreferidos: [...] }` se enviaba sin adaptar a `PATCH /users/me`. Rust espera `generos_favoritos`, por lo que el campo era ignorado silenciosamente por serde y los géneros nunca se persistían.
- **Archivos:**
  - `clients/desktop/src/services/wpJsonRustAdapter.ts`
    - Añadido `/users/me` a `needsAdaptation` (respuesta procesada)
    - Nueva rama en `adaptarRespuesta` para `/users/me` que llama `adaptarUsuario()`
    - Nueva rama en `adaptarBody` para `/users/me` que convierte camelCase → snake_case (nombreVisible→nombre_visible, generosPreferidos→generos_favoritos, avatarUrl→avatar_url, etc.)
- **Gotchas:** La web (`wpJsonStub.ts`) ya manejaba ambos casos. El adaptador desktop solo adaptaba endpoints de auth. Sin la adaptación de body, guardar géneros parecía funcionar (200 OK) pero los datos nunca llegaban a la BD — el modal volvía a aparecer en cada carga porque el backend respondía con `generos_favoritos: null`.
- **Sentinel:** no aplica
- **GLORY:** No aplica
