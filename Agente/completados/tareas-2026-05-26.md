## 265A-1 — Activar burst dinámico de CPU para hostings Coolify
- **Que:** se implementó el primer slice operativo del plan de límites dinámicos. Un nuevo loop background lee snapshots recientes de infraestructura, detecta hostings Coolify que están pegando contra su cap actual y ajusta en caliente `docker update --cpus` sobre el contenedor principal (`site` o `wordpress`). Cuando sube la presión del host o baja la demanda, el loop restaura el baseline contractual del plan.
- **Archivos:** `src/services/cpu_burst.rs`, `src/repositories/infrastructure.rs`, `src/repositories/mod.rs`, `src/services/mod.rs`, `src/main.rs`, `roadmap.md`, `Agente/lecciones/lecciones-aprendidas.md`, `Agente/planes/plan-recursos-hosting-2026-05-22.md`, `Agente/documentacion/hosting/limites-dinamicos-hosting-2026-05-25.md`, `Agente/completados/tareas-2026-05-26.md`
- **Gotchas:** el target real no sale del plan sino de `coolify_site_name` más el servicio efectivo del compose. Mientras no exista una tabla propia de overrides, el loop tiene que reconciliarse contra el límite runtime observado por el sampler para no repetir el mismo `docker update` en cada ciclo.
