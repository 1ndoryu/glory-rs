## 026B-1 — Panel admin: gestión de cobros pendientes (billing_items)

- **Que:** Panel administrativo para gestionar billing_items de todos los usuarios. Permite listar, filtrar por estado (pendiente/pagado), buscar por título o email, y toggle el estado de cada item (paid ↔ pending). Al marcar como pagado se actualiza `paid_at` a NOW(); al revertir a pendiente se limpia `paid_at`.
- **Archivos:**
  - `src/handlers/admin_billing.rs` — Nuevo handler con 2 endpoints: GET list + PATCH toggle status
  - `src/repositories/billing.rs` — `AdminBillingItem` struct + `list_all_for_admin` + `admin_update_status`
  - `src/repositories/mod.rs` — Export `AdminBillingItem`
  - `src/models/billing.rs` — `AdminBillingItemResponse` + `AdminUpdateBillingStatusRequest`
  - `src/models/mod.rs` — Exports nuevos
  - `src/handlers/mod.rs` — Route merge + OpenAPI paths/components
  - `frontend/src/api/admin-billing.ts` — API client (list + update)
  - `frontend/src/hooks/useAdminBilling.ts` — React Query hook con invalidación
  - `frontend/src/components/panel/SeccionCobros.tsx` — Componente admin con filtros, búsqueda, toggle
  - `frontend/src/components/panel/SeccionCobros.css` — Estilos responsive
  - `frontend/src/data/panel.ts` — Tab 'cobros' agregada
  - `frontend/src/components/panel/SidebarPanel.tsx` — Icono ReceiptText
  - `frontend/src/islands/PanelIsland.tsx` — Case 'cobros' switch
- **Gotchas:**
  - `AdminBillingItem` necesita `#[derive(FromRow)]` de sqlx porque se usa con `query_as` (no-macro mode).
  - La query JOIN con users para obtener email: usar alias `bi` y `u` para evitar ambigüedad.
  - Tarjeta como wrapper visual: `.cobrosItem` solo layout (grid), visual via Tarjeta + border-left accent para estado.
- **Sentinel:** Se eliminaron warnings de Code Sentinel al migrar `<input>` → `<Input>`, `<button>` → `<Button>`, `<div className="cobrosItem">` → `<Tarjeta className="cobrosItem">` y quitar spec visual local del CSS.
- **GLORY:** No aplica — funcionalidad específica del admin panel de Nakomi.
