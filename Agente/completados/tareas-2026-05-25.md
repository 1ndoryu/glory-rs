## 255A-2 — Blindar panel de despliegues ante fallos de runtime
- **Que:** `/api/hosting/deployments` dejó de degradar a lista vacía cuando falla `list_services()` de Coolify o del runtime ligero. Ahora reconstruye un fallback mínimo desde `hosting_subscriptions`, deduplica despliegues y devuelve `503` solo si ni siquiera puede recomponer un inventario útil. Durante el cierre del bloque se confirmó además el root cause operativo del `500` global de Coolify en VPS2: `personal_access_tokens.abilities='[*]'` en vez de JSON válido `["]*["]`.
- **Archivos:** `src/handlers/hosting/deployment_helpers.rs`, `src/handlers/hosting/deployments.rs`, `src/services/coolify.rs`, `roadmap.md`, `Agente/lecciones/lecciones-aprendidas.md`, `Agente/completados/tareas-2026-05-25.md`
- **Gotchas:** si la API de Coolify devuelve `500` incluso en `/api/v1/version`, el panel no debe asumir que no existen despliegues; primero revisar Sanctum y el contenido de `abilities` del token.
- **Sentinel:** No aplica
- **GLORY:** No aplica

## 255A-3 — Subir rate limits productivos detrás de proxy
- **Que:** se aumentaron los límites globales de auth y API usando `SmartIpKeyExtractor` para absorber tráfico real de la SPA detrás de Coolify/Traefik y evitar `429` falsos en producción por polling y requests concurrentes.
- **Archivos:** `src/handlers/mod.rs`, `roadmap.md`, `Agente/lecciones/lecciones-aprendidas.md`, `Agente/completados/tareas-2026-05-25.md`
- **Gotchas:** con un proxy compartido, la IP `peer` no representa al usuario final; si los buckets siguen calibrados para tráfico directo, varios clientes comparten límite y producción cae en `429` aunque el backend esté sano.
- **Sentinel:** No aplica
- **GLORY:** No aplica
