## 175A-1 — Critical CSS + lazy islands para PageSpeed 99 mobile

- **Que:** Implementadas dos optimizaciones para mejorar Core Web Vitals en nakomi.studio:
  1. **Plugin `viteDeferCss()`** en `frontend/vite.config.ts`: convierte `<link rel="stylesheet">` en carga no-bloqueante (patrón `media="print" + onload`). Elimina la penalización de 2400ms de render-blocking que PageSpeed reportaba. El spinner inline (ya existente en index.html) aparece inmediatamente sin esperar CSS.
  2. **Lazy loading de islands secundarios** en `frontend/src/App.tsx`: `ServiciosIsland`, `ProyectosIsland` y `NotFoundIsland` convertidos a `lazy()` import. Cada uno tiene ahora su propio chunk separado (2.1 KB cada uno). `BienvenidaIsland` permanece eager (es la ruta principal).

- **Resultados del build:**
  - CSS principal: 39.6 KB → **34.4 KB** (no-bloqueante)
  - JS inicial: 193.1 KB → **186.8 KB**
  - Nuevos lazy chunks: ServiciosIsland-*.js (2.1 KB), ProyectosIsland-*.js (2.1 KB), NotFoundIsland-*.js (0.8 KB)
  - `dist/index.html` generado con `preload as="style"` + `media="print"` + `noscript` fallback ✓
  - TypeScript: sin errores ✓
  - Build: ✓ en 7.70s

- **Archivos:** `frontend/vite.config.ts`, `frontend/src/App.tsx`
- **Commit:** `f47dd73` — `175A-1: Critical CSS + lazy islands para PageSpeed mobile`
- **Deploy:** `redeploy --name studio` iniciado (build Rust en progreso)

- **Gotchas:**
  - El regex del plugin usa `([^>]*)` para capturar atributos antes/después de `href`, y verifica `includes('crossorigin')` para no duplicar el atributo.
  - `viteDeferCss` usa `enforce: 'post'` para correr después que Vite genera el HTML final.
  - ServiciosIsland/ProyectosIsland son wrappers livianos; la reducción del main bundle fue modesta (6.3 KB) porque sus dependencias son compartidas con BienvenidaIsland vía tree-shaking.
